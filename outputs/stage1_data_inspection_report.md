## 1. 本阶段代码说明

本阶段代码解决的问题：自动读取原始 Excel 附件，逐个工作表检查表结构，并把交易明细整理成后续可建模的数据。这样处理的原因是：原始销售数据是一笔一笔的收银记录，而预测模型需要稳定的日期粒度数据。

## 5. 数据质量检查结论

| 检查项 | 结果 | 对后续建模的影响 |
|---|---|---|
| 日期格式是否统一 | 销售 `收款时间` 可解析为 datetime；天气 `日期` 可解析为 datetime | 可以按日期聚合与合并 |
| 销量是否存在负值 | 存在，负销量记录数 54；人工确认表示破损、过期等损耗/冲销类负向调整 | 不作为正常销售需求；本阶段不删除，日销量采用净销量并保留 `negative_adjustment_qty` |
| 销量是否存在极端异常值 | 交易级 `数量` 范围 -24 至 2712；IQR 规则标记 5536 条交易级极端记录 | 后续模型需要比较保留、截尾或单独处理的影响 |
| 商品编号和商品名称是否一一对应 | `商品代码=11001020` 对应两个海苔名称；人工确认合理，名称可能是录入笔误 | 后续以 `product_id` 为准，避免把同一编号拆成两个商品 |
| 门店编号和门店名称是否一一对应 | 门店编号和门店名称双向均未发现非一一对应 | 可用 `store_id` 作为主键，`store_name` 用于展示 |
| 是否存在重复销售记录 | 完全重复行 16605 条；人工确认应保留 | 视为同一时间不同顾客恰好购买数量一致的有效记录，删除会低估销量 |
| 天气数据是否覆盖销售日期 | 缺失销售日期对应外部变量：2022-03-31 | 2022-03-31 无外部变量，合并后保留缺失并标记 `has_external_data=0` |
| 节假日和活动日字段是否可用 | `节日`、`活动日`、`工休日` 均无缺失；人工确认 `活动日` 为促销活动日，`工休日` 为周末/节假日等休息日 | 可以作为问题三和综合模型的外部变量 |
| 是否存在无法合并的日期 | 合并后缺少外部变量的面板行数 81 | 后续建模需决定删除该日、填补或不用外部变量 |
| 是否存在未来信息泄露 | 本阶段只使用同日外部变量和历史交易聚合，未构造未来滚动特征 | 暂未发现未来信息泄露；后续滚动特征必须只用过去数据 |
